## 2. IAM components
#### IAM Policy (Badge)
- a JSON document that defines list of permissions
	- Effect, Action, Resource, and Condition
- can be attached to entities
	- IAM role, users, groups, etc
#### IAM Role (Hat)
- a container that allows a trusted entity to gain temporary permissions
- trust policies
	- who can use (aka assume) this role
- permission policies
	- what badge does this hat has
	- aws managed IAM policies
	- custom IAM policies
	- inline IAM policie
### EC2 Instance profile
- Allows EC2 instances to retrive temporary credentials as a role
- ec2 uses IMDS (Instance metadata service) to vend credentials to the instance

### Some helpful tools
- AWS IAM policy simulator https://policysim.aws.amazon.com/home/index.jsp#

### TDLR Resources to provision
- iam policy `DaaSAppPolicy`
	- has permissions to download a file from s3
	- can be extended for future permissions
- iam role `DaaSAppRole`
	- trust policy
		- can be assumed by all ec2s
	- permissions
		- custom policy `DaaSAppPolicy`
		- aws managed policy `AmazonSSMManagedInstanceCore` to allow access from SSM without SSH
- instance profile `DaaSInstanceProfile`
	- attach iam role to instance profile so that ec2 can assume


## 3. Create the IAM Policy
- 2 ways to build json
	- normally use `jsonencode()` which u can pass into terraform
	- iam has a special `aws_iam_policy_document` data source to work with IAM related json
- search for `aws_iam_policy` in the docs
	- in the example we see the normal `jsonencode()` method
	- and also the `<<EOT EOT` to pass in a json structure string
- search for `aws_iam_policy_document` and convert the below json to that format
	- using the `aws_iam_policy_document` provides better validation and error handling
	- `data` is usually for "reading" or "describing" information
```json
{
	"Version": "2012-10-17",
	"Statement": [
		{
			"Sid": "AllowS3Download",
			"Effect": "Allow",
			"Action": [
				"s3:GetObject",
				"s3:ListBucket"
			],
			"Resource": [
				"arn:aws:s3:::daas-<account-id>",
				"arn:aws:s3:::daas-<account-id>/*"
			]
		}
	]
}
```
- subsequently attach the policy document data into a aws_iam_policy resource

## 4. Create the IAM Role
- we can also build the trust and permission policy for IAM roles using `aws_iam_policy_document`
- the following is how a trust policy looks like
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
			"Sid": "AllowEC2ServiceToAssumeRole",
      "Effect": "Allow",
			"Action": "sts:AssumeRole",
      "Principal": {
        "Service": "ec2.amazonaws.com"
      }
    }
  ]
}
```
- search for `aws_iam_role` in the docs 
	- attach the above trust policy doc in `assume_role_policy`
- subsquently attach the `DaaSAppPolicy` and `arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore` on the iam role resource using `aws_iam_role_policy_attachment`

## 5. The EC2 instance profile
- search for `aws_iam_instance_profile` and attach the `DaaSAppRole` on it


## 6. VPC endpoint for SSM to work
- VPC endpoints are required to communicate with other public AWS services within the AWS network
	- https://docs.aws.amazon.com/vpc/latest/privatelink/create-interface-endpoint.html
- create the following interface VPC endpoints to allow SSM to communicate
	- "ssm", "ssmmessages", "ec2messages"
- for the benefit of time in this workshop, paste the following
```hcl
locals {
  ssm_services = ["ssm", "ssmmessages", "ec2messages"]
}

resource "aws_security_group" "ssm_vpce_sg" {
  name        = "ssm-vpce"
  description = "Allow nodes to talk to SSM Endpoints"
  vpc_id      = aws_vpc.main.id
}

resource "aws_vpc_security_group_ingress_rule" "ssm_vpce_in_https" {
  security_group_id = aws_security_group.ssm_vpce_sg.id
  referenced_security_group_id = aws_security_group.app.id # change accordingly
  ip_protocol = "tcp"
  from_port   = 443
  to_port     = 443
}

resource "aws_vpc_security_group_egress_rule" "ssm_vpce_out_https" {
  security_group_id = aws_security_group.app.id # change accordingly
  referenced_security_group_id = aws_security_group.ssm_vpce_sg.id
  ip_protocol = "tcp"
  from_port   = 443
  to_port     = 443
}

resource "aws_vpc_endpoint" "ssm_endpoints" {
  for_each = toset(local.ssm_services)

  vpc_id            = aws_vpc.main.id
  service_name      = "com.amazonaws.ap-southeast-1.${each.key}"
  vpc_endpoint_type = "Interface"

  subnet_ids = [for s in aws_subnet.private : s.id] # change accordingly

  # This allows the 'ssm.ap-southeast-1.amazonaws.com' URL 
  # to resolve to the private endpoint IP
  private_dns_enabled = true

  security_group_ids = [aws_security_group.ssm_vpce_sg.id]
}
```
