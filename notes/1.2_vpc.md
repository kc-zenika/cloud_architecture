# The VPC

## 1. Main Components
#### VPC
- foundational network isolation unit, scoped to 1 region
- considerations:
  - requires you to plan the entire space upfront, along with future needs/reserves
  - overlapping CIDR will be difficult for peering/tgw
  - organizational level architecture decisions requires some foresight on number of teams/environments, subnets, workloads .... take the whole picture into account
#### Subnets
- subdivisions of a VPC
  - bound to a single AZ
- actual placement boundary for deployed resources
- technically only have public + private subnet types
  - public = bidirectional internet access
  - private = no inbound internet access
- in practice there are many sub categories of private subnets
  - app - has outbound internet
  - db - no outbound, only allow from app subnet
  - intranet - corporate/internal network
  - management - admin tool/utils, admin user access plane
  - firewall - inspection
#### Gateways
- internet gateway (`IGW`)
  - 1 per VPC; attach to VPC to enable internet reachability
  - horizontally scaled, HA, managed by AWS
- NAT gateway (`NATGW`)
  - 90% of the time its for private subnet resources to initiate outbound internet traffic
  - deployed in a public subnet (it needs IGW to reach internet)
  - deploy 1 per AZ of private subnet (for HA and also to avoid cross-AZ traffic cost)
#### Route tables
- a set of rules (routes) that tell network traffic in your subnet where to go.
  - a subnet is a public subnet when it has a route towards a IGW
- destination CIDR → target
- each subnet has exactly 1 associated route table
- uses longest prefix match
- the `local` route
  - your VPC internal
  - can think of it as a backport
#### NACL
- stateless, subnet-level firewall — evaluated on EVERY packet (inbound AND outbound independently)
  - **stateless** = return traffic must be explicitly allowed
- operates at the subnet boundary, before traffic reaches any resource
- each subnet can only have 1 NACl
- rules have priority and are evaluated in order
- in practice - use NACL as a course perimeter
#### Security groups
- stateful, resource-level virtual firewall (EC2, RDS, ALB, Lambda ENI, etc.)
  - **stateful** = return traffic is automatically allowed, no egress rule needed for responses
- attached to ENIs (elastic network interfaces), not subnets — more granular than NACLs
- rules are ALLOW only — no explicit deny; unmatched traffic is implicitly denied
- can reference other SGs as sources (not just CIDRs) — enables clean tier-to-tier rules
- in practice - use sec-groups for fine grain control (per resource type)

## 3. Create a VPC
- on the terrform provider documentation page, navigate to `VPC (Virtual Private Cloud)` page
- search for `aws_vpc` and follow the Basic usage example
- will require `enable_dns_support` and `enable_dns_hostnames` to be true
- lets add some tags
```json
{
  "Name": "vpc-main", // almost all (but not all) resources follow this Name tag
  "Environment": "dev" // just for demo
}
```

## 4. Adding subnets
- search for `aws_subnet` and follow the Basic usage example
- create 3 of the public subnets 
  - reference the vpc_id with `aws_vpc.main.id`
  - define the `cidr_block` and `availability_zone`

### optimization/DRY
- to perform a for loop, we can use the `for_each` reference in terraform
```hcl
locals {
  public_subnets = {
    "ap-southeast-1a" = "10.0.0.0/22"
    "ap-southeast-1b" = "10.0.4.0/22"
    "ap-southeast-1c" = "10.0.8.0/22"
  }

  private_subnets = {
    "ap-southeast-1a" = "10.0.32.0/19"
    "ap-southeast-1b" = "10.0.64.0/19"
    "ap-southeast-1c" = "10.0.96.0/19"
  }
}

resource "aws_subnet" "public" {
  for_each = local.public_subnets

  vpc_id            = aws_vpc.main.id
  availability_zone = each.key
  cidr_block        = each.value

  tags = {
    Name        = "public-${each.key}"
    Environment = "dev"
  }
}
```
- repeat the same for private subnets

#### Terraform plan and apply
- create the VPC and subnets at this stage
```bash
terraform init # since we added the aws provider in the previous step
terraform plan
terraform apply # to create the VPC
```
- view the created resources on aws console
  - AWS console > VPC
  - and see your VPC (yayyy)

## 6. Route table to route public subnets to IGW
- `aws_route_table` (Name: `rt-public`)
  - with 1 route from "0.0.0.0/0" to igw-main
  - this is what makes a subnet "public"
- `aws_route_table_association`
  - associate this `rt-public` route table with all our public subnets
- we can use `for_each` again here
```hcl
resource "aws_route_table_association" "public" {
  for_each = aws_subnet.public
  subnet_id      = each.value.id
  route_table_id = aws_route_table.public.id
}
```
Visualize the flow on AWS Console
  - VPC > Click on VPC and view resource map
  - see that public routes to IGW, and private doesnt (associated with default route table (created with VPC))


## 7. Adding NACL
- there are 2 ways to manage these
1. using `aws_network_acl` directly
  - already exposes subnet association, egress and ingress rules 
2. using a set of these resources
  - `aws_network_acl` - to create a nacl
  - `aws_network_acl_association` to associate a nacl to a subnet
  - `aws_network_acl_rule` to create a nacl rule on a nacl
- option 1: compact, all in one resource
- option 2: independent resources, can modify one without another
- for today, lets just keep it to option 1.
