# EC2
## Selection criteria
- Instance family
	- https://aws.amazon.com/ec2/faqs/#instance-types--7oj3fi
	- https://aws.amazon.com/ec2/instance-types/
	- normally - general purpose(m), compute(c)/memory(r) optimized, burstable(t)
- Architecture
	- x86 and ARM (Graviton) - effective cost savings ~40%
- AMI - amazon machine image
	- template for root volume
		- contains OS, kernel, preinstalled software
		- permissions, block device mapping
	- immutable - think of it as a read-only snapshot
	- can build custom AMI
	- golden AMI = hardened, validated, and authorized custom AMI
	- CIS benchmarks https://www.cisecurity.org/benchmark/amazon_linux
		- check using AWS Inspector does some scans
	- `packer` - https://developer.hashicorp.com/packer/tutorials/aws-get-started/aws-get-started-build-image
		- spins up a temporary instance, automation/verification scripts
		- runs hardening/benchmarking scripts 
		- provisions your AMI on EC2
- Storage
	- persistance
		- lifecyle of data is tied to the lifecycle of the volume, not the instance
		- normally an instance has 2 volumes - root/OS (disposable) + data volume (persist/grow)
		- increasing size of volume can be done on the fly without stopping the instance (shrinking needs migration)
	- performance
		- IOPS (speed of R/W) and Throughput (volume of data moved)
		- normally - general purpose SSD (gp3/gp2), IOPS SSD (io2/io1)
		- can use "cheaper" volume for OS volume, and higher speed gp3 for data
## Instance metadata
- https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instancedata-data-retrieval.html
- instance metadata service (IMDSv2)
- a special nonroutable address http://169.254.169.254
	- Instance ID, AMI ID, hostname
	- IAM role credentials (Instance profile)
	- network info - VPC ID, AZ, security group, etc
- identity of your instance - (think Singpass)
## User Data
- Script that runs exactly once during boot
- Running setup commands
- Bootstrapping server
- runs as root user
- cat `/var/log/cloud-init-output.log` for debugging

## NAT
- create a NAT gateway `nat-main`
	- we will create only 1 for cost savings, but generally theres 1 per AZ for HA
	- recap: _Which subnet the NAT needs to live in?_
- search for `aws_nat_gateway` in the docs
- we will also need a `aws_eip` with domain = vpc
	- as a static public IP for the NAT
	- this static IP would be how your out bound traffic from your private subnets appears on the internet
	```hcl
	resource "aws_eip" "nat" {
		domain = "vpc"
		tags = {
			Name = "nat-eip"
		}
	}
	```
- associate the elastic IP to `nat-main` in `allocation_id`
- `depends_on` = internet gateway 
	- this will ensure the internet gateway is created first
	- terraform handles the ordering
### route private subnet to NAT
- any other packets that are not to the vpc (10.0.0.0/16) would be towards 0.0.0.0/0
- Private Route table - `rt-private`, associated to private-1a/b/c

  | Destination | Target   | Notes                     |
  |-------------|----------|---------------------------|
  | 10.0.0.0/16 | local    | intra-VPC, auto-added     |
  | 0.0.0.0/0   | nat-main | outbound internet via NAT |
- can reference the previous `aws_route_table` and `aws_route_table_association` for `rt-public`
	- instead of `gateway_id` we can use `nat_gateway_id` (its a aws provider issue)

## VPCe
- AWS S3 requires a special VPCe gateway type (`vpc_endpoint_type = "Gateway"`)
	- _Do you know which other resource requires gateway VPCe type?_
- For service name, its `com.amazonaws.ap-southeast-1.s3`
- For gateway VPC e, we can use `route_table_ids`, 
	- automatically injects a route in to the route table ids specified here
	- doesnt need a ENI/Ip address
```hcl
resource "aws_vpc_endpoint" "s3" {
  vpc_id       = aws_vpc.main.id
  service_name = "com.amazonaws.ap-southeast-1.s3"
  vpc_endpoint_type = "Gateway"

  # This automatically injects the S3 route into these route tables
  route_table_ids = [aws_route_table.private.id]
}
```
